Casino bonus scraper

Scrapes the welcome offers of the first 3 casinos on one public comparison page
(<https://www.gambling.com/uk/online-casinos/bonus>), uses an LLM to turn the
free-text terms into structured fields, and shows them on a single mobile-friendly page.

Files

- `scrape.py` – fetch, parse, LLM extraction, writes `bonuses.json`
- `bonuses.json` – output (generated by the script, not typed by hand)
- `index.html` – renders `bonuses.json`, readable on a phone
- `test_parse.py` – offline test of the HTML parsing and output validation
- `WRITTEN.md` – production plan for 200 casinos, updated daily

Install and run

```bash
pip install -r requirements.txt
export GEMINI_API_KEY=...                 # Windows PowerShell: $env:GEMINI_API_KEY="..."
python scrape.py                          # writes bonuses.json
python -m http.server 8000                # then open http://localhost:8000
```

The language-model step uses the Google Gemini API; a free key (no card) comes from
<https://aistudio.google.com/apikey>. Optional: `GEMINI_MODEL` overrides the model
(default `gemini-2.5-flash`).

Fields per casino

| Field | Example |
|---|---|
| `welcome_bonus` | `100% up to £50 + 11 free spins` |
| `wagering_multiplier` | `10` (`0` = none, `null` = not stated) |
| `minimum_deposit` | `£10` (`null` = not stated) |
| `source_url` | page the data came from |

Behaviour

- Checks `robots.txt` before fetching (the bonus page is allowed for generic crawlers at time of writing).
- Does not bypass logins, CAPTCHAs or blocks. On a 401/403/429 it stops and tells you to switch source.
- The LLM is told to return `null` rather than guess; output is validated before it is written.
- The script fails loudly if fewer than 3 offers are found (layout change), rather than writing partial data.

AI Usage & Reflection
Tool Used: Claude 

AI Error & Correction: The AI initially generated a regex selector that targeted static news articles rather than the main casino listing cards. Additionally, it extracted wagering requirements as strings containing the text "35x" instead of parsing them into clean integer multipliers (35). I caught this during data verification in bonuses.json and adjusted the DOM selector logic and prompt instructions to enforce strict integer parsing.

Time Spent: ~2.5 hours total (Scraper & LLM integration: 1 hr | Frontend & Deployment: 45 mins | Written Architecture section: 45 mins).
